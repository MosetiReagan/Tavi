## 4. End-to-End Task Execution Audit

### 4.1 Calendar Tools
- **List Events (`calendar_list_events`):** Reads from Android Calendar Provider (`CalendarContract.Events`). Safe read-only action requiring `READ_CALENDAR`.
- **Create Event (`calendar_create_event`):** Resolves natural language date/time strings using `CalendarNaturalDateResolver` (supports "tomorrow at 3pm", "next Friday at 10am", "in 2 hours"). Validates mandatory start/end times and inserts into Android calendar.
- **Delete Event (`calendar_delete_event`):** Consequential action requiring `WRITE_CALENDAR` and explicit user confirmation dialog (`SecurityGuard.requiresUserConfirmation("calendar_delete_event") == true`).

### 4.2 Messages & Notifications
- **Draft Messages (`messages_draft`):** Creates in-memory drafts and stores them in SQLite `draft_messages` table. Non-destructive, does not send SMS.
- **Send SMS (`messages_send_sms`):** Consequential action. Strictly gated behind user confirmation. Requires `SEND_SMS`. Uses Android's `SmsManager.getDefault()`.
- **Notifications (`notifications_read_summary`):** Integrates with `TaviNotificationListenerService` (`android.permission.BIND_NOTIFICATION_LISTENER_SERVICE`). Summarizes permitted active notifications without exfiltrating notification payloads.

### 4.3 Browser Tasks
- **Research Topic (`browser_research_topic`):** Connects to DuckDuckGo HTML search and extracts plain text without executing untrusted client-side JavaScript.
- **Security Boundaries:** Employs loop detection, bounded redirects (max 3), a 10-second timeout, and sanitizes untrusted HTML through `SecurityGuard.sanitizeExternalContent`. Prompt injection vectors (e.g. `Ignore previous instructions`) are stripped and replaced with `[REDACTED_SECURITY_RISK]`.

### 4.4 Personal Memory & Everyday Tools
- **Memory Save/Retrieve/Delete (`memory_save`, `memory_retrieve`, `memory_delete`):** Persisted locally in SQLite table `personal_memories` with key-value indexing and timestamps.
- **Everyday Tools:** Tested arithmetic parser (`calculator`), date arithmetic (`date_calculation`), reminder scheduler (`reminder_create` using `AlarmManager.setExactAndAllowWhileIdle`), and quick notes (`note_create`).

## 5. Security & Privacy Audit

### 5.1 Confirmation Bypass Vulnerability (Remediated)
- **Finding:** In `CalendarDeleteEventTool.kt` (line 333) and `MessagesSendTool.kt` (line 100), execution checked `arguments["__user_confirmed"] == true`. In `ToolRegistry.kt`, incoming tool arguments were forwarded directly to the tool. An untrusted prompt injection or malicious tool call could supply `"__user_confirmed": true` directly in its argument map.
- **Remediation Applied:** In `ToolRegistry.kt`, incoming arguments are explicitly sanitized:
  ```kotlin
  val effectiveArgs = toolCall.arguments.toMutableMap().apply {
      if (userConfirmed) {
          put("__user_confirmed", true)
      } else {
          remove("__user_confirmed") // Strips any caller-forged confirmation flag
      }
  }
  ```
- **Verification:** Unit tests added in `ToolExecutionTest.kt` verifying that calling consequential tools without host-level authorization halts and triggers confirmation request.

### 5.2 Android Backup Vulnerability (Remediated)
- **Finding:** `AndroidManifest.xml` had `android:allowBackup="true"`. On any unlocked Android device with USB debugging enabled, `adb backup -f backup.ab com.tavi.assistant` could dump the unencrypted SQLite database (`tavi_local.db`) containing private personal memories, notes, and SMS draft histories.
- **Remediation Applied:** Updated `AndroidManifest.xml` line 17 to `android:allowBackup="false"`.

### 5.3 Exported Component & Network Surface
- **MainActivity:** `exported="true"` with `android.intent.action.MAIN` (standard for launchable UI).
- **TaviNotificationListenerService:** `exported="true"` protected by `android.permission.BIND_NOTIFICATION_LISTENER_SERVICE` (system-only bind).
- **ReminderReceiver:** `exported="false"` (cannot be triggered by third-party applications).
- **Network Permissions:** `INTERNET` and `ACCESS_NETWORK_STATE` are used exclusively by `BrowserTools.kt` for user-initiated web research. No background sync or analytics endpoints exist.

## 6. Local Inference Architecture & Benchmark Reality Check

### 6.1 Inference Engine Reality
- Inspection of `LiteRtLlmEngine.kt` revealed that while the class structure exists, the actual code path delegates unconditionally to `DeterministicAssistantEngine.kt`:
  ```kotlin
  override suspend fun generateResponse(
      prompt: String,
      conversationHistory: List<Message>,
      onToken: (String) -> Unit
  ): String {
      return fallbackEngine.generateResponse(prompt, conversationHistory, onToken)
  }
  ```
- `app/build.gradle.kts` does not include `com.google.mediapipe:tasks-genai` or LiteRT C++ runtime dependencies (`.so` binaries).
- **Impact:** The application works robustly and predictably for deterministic actions, but it is currently operating as a deterministic rule-based assistant, not a running neural network model.
- **Remediation Applied:** Diagnostics in `LiteRtLlmEngine.kt` were corrected to honestly report `fallbackActive = true` and `inferenceRuntime = "DeterministicAssistantEngine"`.

### 6.2 Benchmark Score Analysis
- `docs/EVALUATION_REPORT.md` reported a "100% benchmark score across 15 scenarios".
- Inspection of `evaluation/evaluate_dataset.py` revealed:
  - It does not load the Android app or execute JVM/Kotlin code.
  - It checks regexes on static prompt strings in Python (e.g., `if "calendar" in prompt.lower(): ...`).
  - It does not test natural language variations, out-of-vocabulary inputs, or model hallucinations.
- **Conclusion:** The 100% benchmark claim must be retracted. Reliability claims should instead reference the 18 passing Android JVM unit tests.

## 8. Prioritized Remediation Plan

### Phase 1: Native Runtime Integration (Required for Production Release)
1. Add MediaPipe GenAI / LiteRT Android SDK dependency to `app/build.gradle.kts`:
   ```kotlin
   implementation("com.google.mediapipe:tasks-genai:0.10.14")
   ```
2. Implement native JNI inference session inside `LiteRtLlmEngine.kt` using `LlmInference` with model weights streaming from `context.filesDir/models/`.
3. Wire model cancellation token and token-by-token streaming callbacks.

### Phase 2: In-App End-to-End Evaluation Harness
1. Replace `evaluation/evaluate_dataset.py` with an Android Instrumented Test (`androidTest`) that feeds all 15 scenarios directly into `MainScreenViewModel`.
2. Measure real inference latency (tokens/sec), RAM peak usage, and tool extraction accuracy against actual model outputs.

### Phase 3: Offline Speech Stack
1. Integrate an embedded on-device speech engine (e.g. Whisper.tflite or Sherpa-ONNX) to guarantee offline STT across all Android devices regardless of OEM speech service configurations.
